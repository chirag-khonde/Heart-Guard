# HeartGuard Patient History, Analytics, Trends & Report Generation (Phase 10)

## 1. Overview & Architecture

HeartGuard Phase 10 introduces a complete historical analytics, longitudinal trend tracking, and professional PDF report generation subsystem. It acts strictly as an analytics and reporting consumer over the multimodal cardiovascular predictions generated by Phase 7 and the alert outcomes produced by Phase 8.

## 2. Assessment Data Model & Schema

Assessment records are persistently stored in an isolated SQLite database at `data/assessments/assessments.db`. All database queries strictly utilize parameterized bindings (`?`) to prevent SQL injection.

### Table Schema: `assessments`

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | Internal row identifier. |
| `assessment_id` | `TEXT NOT NULL UNIQUE` | Cryptographically safe unique string identifier (e.g. `uuid.uuid4().hex[:8]`). |
| `user_id` | `INTEGER NOT NULL` | Authenticated user foreign key; enforces strict patient-data isolation. |
| `created_at` | `TEXT NOT NULL` | ISO 8601 UTC timestamp of assessment completion. |
| `clinical_risk` | `REAL NOT NULL` | Raw clinical machine learning prediction percentage ($0.0 - 100.0\%$). |
| `lifestyle_risk` | `REAL NOT NULL` | Raw quantified lifestyle NLP risk score ($0.0 - 100.0$). |
| `overall_risk` | `REAL NOT NULL` | Multimodal weighted risk score ($70\%$ clinical $+ 30\%$ lifestyle). |
| `risk_category` | `TEXT NOT NULL` | Categorical risk classification (`CRITICAL`, `ELEVATED`, `LOWER_RISK`). |
| `recommendation` | `TEXT NOT NULL` | Actionable clinician recommendation string from the multimodal engine. |
| `model_version` | `TEXT NOT NULL` | Active model identifier and version string for audit traceability. |
| `narrative_summary` | `TEXT` | Qualitative multi-sentence explanation produced during evaluation. |
| `alert_status` | `TEXT NOT NULL` | Emergency dispatch state (`NOT_TRIGGERED`, `DISABLED`, `SUCCESS`, `FAILED`). |
| `top_clinical_factors_json` | `TEXT` | JSON-serialized top 5 SHAP clinical risk drivers with impact weights. |
| `lifestyle_factors_json` | `TEXT` | JSON-serialized safe lifestyle risk signals (category, severity, points). |
| `clinical_data_json` | `TEXT` | JSON-serialized physiological metrics (blood pressure, cholesterol, etc.). |

## 3. Patient Data Isolation & Access Controls

- **Database-Level Isolation:** Patient records are filtered at the database/service layer (`WHERE user_id = ?`). The application never loads records for multiple patients and filters them in-memory in the UI.
- **Ownership Verification:** Before viewing, generating a PDF report, or exporting CSV records, the system executes `HistoryService.user_owns_assessment(user_id, assessment_id)`. If unauthorized, a `PermissionError` is raised.
- **Admin Privacy Protection:** The administrative portal (`pages/admin.py`) provides system-wide aggregated metrics (`total_assessments`, `category_distribution`, `model_version_distribution`) without exposing individual patient names, contact details, or lifestyle narratives.

## 4. Longitudinal Risk Trends & Comparative Analytics

### Chronological Ordering
Historical assessments are queried in ascending chronological order (`ORDER BY created_at ASC`) to ensure accurate trend plotting.

### Pairwise Comparison
When at least two assessments exist, `TrendService.compare_assessments()` computes:
$$\Delta_{\text{overall}} = \text{Overall Risk}_{\text{latest}} - \text{Overall Risk}_{\text{previous}}$$
$$\Delta_{\text{clinical}} = \text{Clinical Risk}_{\text{latest}} - \text{Clinical Risk}_{\text{previous}}$$
$$\Delta_{\text{lifestyle}} = \text{Lifestyle Risk}_{\text{latest}} - \text{Lifestyle Risk}_{\text{previous}}$$

Changes are presented explicitly in **percentage points** (e.g. `+8.0 percentage points`), avoiding misleading relative percentage claims.

### Prudent Non-Diagnostic Trend Interpretation
Trend descriptions adhere strictly to non-diagnostic phrasing:
- *"Overall model-based risk has increased compared with the previous assessment."*
- *"Overall model-based risk has decreased compared with the previous assessment."*
- *"Overall model-based risk is unchanged compared with the previous assessment."*

## 5. Professional PDF Report Generation

Built with **ReportLab** (`reportlab>=4.0.0`), reports follow a four-page structured layout formatted specifically as an academic research prototype:

1. **Page 1 — Executive Summary:**
   - HeartGuard title, "Academic/Research Prototype" classification.
   - Metadata block: Assessment ID, Date, Model Version, Masked Alert Status.
   - Prominent Overall Risk score callout with color-coded category banner and recommended action.
2. **Page 2 — Component Breakdown & Explainability:**
   - 70/30 Multimodal formula table with raw scores, weights, and weighted point contributions.
   - Top 5 SHAP clinical risk drivers table with impact values (or fallback note if SHAP was omitted).
   - Detected lifestyle cardiovascular risk signals table.
3. **Page 3 — Historical Context & Trend Trajectory:**
   - Pairwise comparison table against the immediately preceding assessment.
   - Longitudinal risk trend trajectory line chart (rendered via Matplotlib and embedded as high-resolution PNG).
4. **Page 4 — Alert Information & Medical Disclaimers:**
   - Emergency dispatch outcome and privacy-masked recipient information.
   - Emergency advice callout for critical assessments ($> 85\%$).
   - Comprehensive academic prototype and medical safety disclaimers.

## 6. CSV Data Export & Security

Patients can export their assessment history to CSV via `pages/history.py`:
- **Isolation:** Includes only records belonging to the authenticated user.
- **Formula Injection Mitigation:** To prevent CSV formula injection when opening exports in Microsoft Excel or Google Sheets, fields starting with `=`, `+`, `-`, or `@` are automatically sanitized with a leading single quote (`'`).
- **Data Minimization:** Excludes internal database keys, password hashes, and Twilio credentials.

> **Medical Disclaimer:** HeartGuard is an academic/research prototype for AI-based heart disease risk assessment. It is not a medical diagnostic system and does not replace evaluation by a qualified healthcare professional.
>
> **Trend Interpretation Notice:** Changes in HeartGuard risk scores represent changes in the model's assessment inputs and outputs. They do not by themselves establish a medical diagnosis or disease progression.
